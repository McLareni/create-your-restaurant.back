# 🛠️ Шпаргалка команд розробки та деплою (Gustio Backend)

Цей документ містить усі основні команди, необхідні для розробки, перевірки якості коду, роботи з базою даних, генерації ключів локалізації та тестування email-шаблонів.

---

## 🚀 1. Запуск та Збірка Проекту

* **`npm run start:dev`** — Запуск локального сервера розробки у режимі гарячого перезавантаження (watch mode). Сервер автоматично перезапускається при зміні будь-якого файлу в `src/`.
* **`npm run build`** — Генерує Prisma Client та компілює TypeScript-код проекту в JS у папку `dist/`. Використовується для підготовки проекту до деплою на продакшн.
* **`npm run start:prod`** — Запуск вже зкомпільованого продакшн-сервера з папки `dist/`.

---

## 🧹 2. Гігієна Коду (Форматування та Лінтинг)

* **`npm run lint`** — Запуск ESLint для перевірки коду на логічні помилки, невідповідність типізації, відсутність ключів перекладу у DTO та порушення правил проекту.
* **`npm run format`** — Запуск Prettier для автоматичного форматування коду (вирівнювання відступів, розривів рядків та крапок з комою) у папках `src/`, `test/` та `scripts/`.

### 💡 Послідовний запуск (Форматування + Перевірка):
> **Важливо для Windows (PowerShell):**
> ```powershell
> npm run format ; npm run lint
> ```
> **Для macOS / Linux / Git Bash:**
> ```bash
> npm run format && npm run lint
> ```

---

## 🌐 3. Локалізація та Переклади (i18n)

* **`npm run i18n:extract`** — Автоматичний скрипт збору ключів перекладу (`scripts/extract-i18n.ts`).
  * **Що робить:** Сканує всі `.ts` файли у папці `src/`, знаходить усі ключі помилок/відповідей (`errors.*`, `success.*`, `auth.*`, `api.*`, `responses.*`) та автоматично створює/оновлює JSON-файли у папках `src/i18n/uk/` та `src/i18n/en/`.
  * **Безпека:** Нові ключі додаються зі значенням `"TODO: Translate..."`, а вже існуючі переклади **ніколи не видаляються і не перезаписуються**.

---

## ✉️ 4. Розробка та Тестування Email-шаблонів

* **`npm run email:preview`** — Запуск локального HTTP-сервера для миттєвого тестування верстки email-шаблонів без відправки реальних листів через Resend.
  * **Як використовувати:** Після запуску відкрий у браузері `http://localhost:3002`. При зміні HTML-коду в шаблонах (`src/users/templates/`), зупини скрипт (`Ctrl+C`), запусти знову та онови сторінку браузера.

---

## 🗄️ 5. Робота з Базою Даних (Prisma ORM)

* **`npx prisma migrate dev`** — Створення та застосування нової міграції БД на основі змін у `prisma/schema.prisma`. Також автоматично оновлює Prisma Client.
* **`npx prisma generate`** — Примусова генерація типів Prisma Client без внесення змін у базу даних.
* **`npx prisma studio`** — Запуск візуального веб-інтерфейсу у браузері (за замовчуванням `http://localhost:5555`) для зручного перегляду та редагування даних у БД.

---

## 🔒 6. Контроль Якості (Husky Git Hooks)

* **`npx husky init`** — Ініціалізація перехоплювачів Git у проекті (виконується один раз при налаштуванні середовища).
  * **Файл `.husky/pre-commit`:** Повинен містити команду `npm run lint && npm run format`. Це автоматично перевіряє код перед кожним комітом і не дозволяє відправити в репозиторій код із помилками або без ключів перекладу.
